# 教学计划规划器

## 概述

本技能服务于个性化一对一教师，为某个学生规划「一个阶段」的教学计划，输出按课次排列的完整方案。核心是**学情驱动**：先诊断学生现状（薄弱点、考试错题、听评课反馈、成绩），再结合可上课次数与教师提供的教案库，挑选每节课该讲的内容与知识点。

## 适用场景

- 教师想为某学生规划「未来 N 次课」上什么。
- 教师提供一批教案文件，让 AI 判断「该上哪些、按什么顺序上」。
- 结合学生错题、考试成绩、听评课记录，针对性安排教学内容。
- 生成可打印的教学计划（默认 Excel `.xlsx`，A4 打印友好）。

## 数据目录结构

统一使用英文命名，存放于工作区 `e:\codebuddy\workflow\teaching-plan\`：

```
teaching-plan/
├── lesson-plans/                  # 教师提供的教案文件（.pdf/.docx/.md）
│   ├── {教案名}.pdf
│   └── _index.json                # 教案索引（解析后生成，机器可读）
├── student-snapshots/             # 学情快照（每次规划时汇总的学生现状）
│   └── {学生}_{YYYYMMDD}.json
└── plans/                         # 生成的教学计划（Excel）
    └── {学生}_{阶段名}_教学计划.xlsx
```

> 关联读取的既有数据（只读，不修改）：
> - 错题：`student-profiles/students/{学生}.json`
> - 听评课报告：`classroom-evaluation-output/reports/`
> - 考试分析：`exam-paper-output/{学科}/`

## 教案索引（_index.json）

教师提供的教案文件解析后，抽取元信息建立索引，每条：

```json
{
  "id": "LP-001",
  "title": "二次函数最值专题",
  "subject": "数学",
  "grade": "初三",
  "knowledge_points": ["二次函数", "最值", "配方法"],
  "difficulty": "中等",
  "lesson_count": 2,          // 预计需要的课次数
  "file": "二次函数最值专题.pdf",
  "summary": "一句话简介",
  "status": "候选"            // 候选 / 已用 / 跳过
}
```

## 学生学情快照（student-snapshots）

规划前，汇总学生现状为快照，作为规划输入：

```json
{
  "student": "连可欣",
  "date": "2026-09-05",
  "grade": "高三",
  "subjects": ["物理"],
  "weak_points": [            // 从错题/考试聚合的薄弱知识点
    {"knowledge_point": "电磁感应", "error_count": 2, "priority": "高"},
    {"knowledge_point": "几何光学", "error_count": 1, "priority": "中"}
  ],
  "recent_exam": {            // 最近一次考试情况
    "name": "顺德一中第四届物理运算",
    "date": "2026-09-05",
    "score": null,            // 若教师提供则填
    "note": ""
  },
  "observation_feedback": [   // 从听评课报告提取的课堂反馈
    "审题不够仔细",
    "计算步骤需规范"
  ],
  "available_lessons": 8,     // 本阶段可上课次数（教师提供）
  "stage_goal": "",            // 阶段目标（教师提供，如"期中考试前巩固薄弱点"）
  "score_goal": "",            // 阶段成绩目标（如"暂时稳定在85分"）
  "lesson_feedback_basis": []   // 后续每节课由错题/课堂反馈沉淀的复习依据
}
```

## 核心工作流

### 第一步：收集学情

1. 确认学生姓名、阶段（可上课次数、阶段目标）。
2. 读取该学生的错题数据（`student-profiles/students/{学生}.json`），聚合薄弱知识点（按 `knowledge_point` 统计出错次数）。
3. 读取最近考试分析（`exam-paper-output/`），了解考试暴露的问题。
4. 读取听评课报告（`classroom-evaluation-output/reports/`），提取课堂反馈（审题、计算、习惯等）。
5. 若有成绩信息（教师口头提供），记录到快照。
6. 生成学情快照 `student-snapshots/{学生}_{YYYYMMDD}.json`。

### 第二步：解析教案

1. 教师提供教案文件（PDF/Word/MD），先放到 `lesson-plans/`。
   - PDF 用 pdf 技能解析，Word 用 docx 技能解析，MD 直接读取。
2. 从每份教案抽取：标题、学科、适用学段、知识点、难度、预计课时数、一句话简介。
3. 写入 `_index.json`（若已存在则合并更新，不覆盖已有条目）。

### 第三步：诊断与匹配

1. 对比「学生薄弱点」与「教案知识点」，找出**该优先上的教案**（覆盖薄弱点的教案排前）。
2. 结合阶段目标（如"期中巩固"）与可上课次数，判断：
   - 哪些教案必上（覆盖高频薄弱点）
   - 哪些可上（巩固/拓展）
   - 哪些暂缓（学生已掌握或与目标无关）
3. 对每份教案给出「选用 / 跳过」建议及理由。

### 第四步：排定课次计划

按「课次」排定前，必须先处理教师已提供的教案库：

1. 不只浏览文件名；需要详细阅读接下来预计要上的 2-3 份教案。
2. 对每份教案提取：核心知识点、题型目录、题型对应题号、基础必做题、优先掌握题、可选拔高题。
3. 修改后续教学计划时，优先依据这些已读教案进行概括，而不是泛泛写“相似/函数/复习”。
4. 若前面课次已有「当堂课掌握情况」中的薄弱点，新课安排要与后续 2-3 份教案内容交叉匹配。

按「课次」输出：

| 课次 | 教学主题 | 课堂重点 | 当堂课掌握情况 |
|------|----------|----------|----------------|
| 第1课 | ... | ... | 待课后反馈填写 |

排课原则：
1. **薄弱点优先**：出错次数多、优先级高的知识点先排。
2. **难度递进**：先基础巩固，再中等，后拔高。
3. **留复习余量**：每 3-4 课留一节复习/查漏。
4. **关联可追溯**：每节课标注「为什么上这个」（关联到具体错题/考试/听评课反馈）。

### 第五步：课后反馈滚动更新

当教师课后补充「本节课使用的教案/试卷」与「错题题号/课堂表现」时：

1. 先定位对应教案或试卷，提取错题所在题型、知识点、考查方法。
2. 不把错题清单简单写进「课堂重点」；课堂重点只写本节课讲授内容和训练目标。
3. 将错题分析写入该课次的「当堂课掌握情况」，格式建议为：
   - `错题：...`
   - `暴露问题：...`
   - `后续复习重点：...`
4. 这些掌握情况记录必须作为后续排课、复习课、阶段检测讲评的依据。
5. 若暂时没有反馈，「当堂课掌握情况」保持空白，不写占位文字。

### 第六步：输出计划

生成教学计划（默认 Excel `.xlsx`，A4 打印友好），内容含：
1. **学生概况**：姓名、年级、学科、阶段目标、阶段成绩目标、可上课次数。
2. **学情诊断**：薄弱点清单（按优先级）、考试情况、听评课反馈。
3. **课次计划表**：逐课次的教学主题、课堂重点、当堂课掌握情况。
4. **建议**：留给复习的余量、课后练习建议。
5. **打印格式**：A4 横向、适应 1 页宽、冻结表头、重复打印标题行、自动换行、合理列宽与行高。

### 第七步：自我总结与 Skill 优化

同其他 skill：复盘踩坑（解析、编码、匹配逻辑），固化为规则，追加 `CHANGELOG.md`，用统一脚本一键清理 `_tmp/`（见「临时文件规范」）。

## 输出文件保存规范

- 学情快照：`teaching-plan/student-snapshots/{学生}_{YYYYMMDD}.json`
- 教案索引：`teaching-plan/lesson-plans/_index.json`
- 教学计划：`teaching-plan/plans/{学生}_{阶段名}_教学计划.xlsx`（默认 Excel，A4 打印友好）
- 中文内容写入文件时用 UTF-8 临时脚本，避免 GBK 乱码（文件名一律英文）。

## 运行环境避坑（Windows 中文编码）

与 `exam-paper-analyzer`、`student-error-tracker` 相同的坑：命令行直接写中文参数/路径会乱码。规则：
1. 文件名/目录名一律英文。
2. 中文内容（学生名、教案标题等）通过 UTF-8 临时脚本硬编码写入，或直接写进 JSON/MD 文件内容（UTF-8 读写）。
3. JSON 读写显式 `encoding="utf-8"`、`ensure_ascii=False`。

## 临时文件规范（工作区统一约定）

- 运行中的一切临时文件（UTF-8 中文脚本、教案解析中间产物、渲染缓存等）**统一放入工作区 `_tmp/` 目录**（已被 `.gitignore` 排除），禁止散落在根目录或正式数据目录（`teaching-plan/` 等）。
- 结束时执行**一条命令**一键清理，禁止逐个文件删除（会多次打扰用户确认）：

  ```
  python .codebuddy/scripts/cleanup_tmp.py
  ```

  支持 `--dry-run`（预览不删）与 `--legacy`（额外清理根目录遗留 `*_work/` 目录）。脚本只删 `_tmp/`，不触碰任何正式目录。
