# 学生错题管理与针对性出题

## 概述

本技能服务于个性化一对一教师，构建「错题记录 → 薄弱点诊断 → 定期复习 → 针对性出题 → 掌握追踪」的闭环。以学生为中心，用结构化 JSON 沉淀数据（便于机器自动出题与追踪），同时生成可读的 Markdown 档案供教师人工查看。

## 适用场景

- 每次考试后，记录某学生做错的题目（从试卷分析结果中提取）。
- 建立/维护学生错题本，按知识点聚合薄弱点。
- 定期复习错题，生成「今日该复习」清单。
- 针对某个错题，推荐同考点、同题型、同难度或升一档难度的练习题。
- 追踪学生后续是否掌握（重做结果），更新能力画像。

## 数据目录结构

所有学生数据存放在工作区 `e:\codebuddy\workflow\student-profiles\` 下：

```
student-profiles/
├── students/
│   └── {学生姓名}.json          # 学生档案 + 错题库（机器可读主数据）
│   └── {学生姓名}.md            # 学生档案（可读视图，从 JSON 生成）
└── exams/
    └── {YYYYMMDD}_{学生}_{学科}.md   # 每次考试的试卷分析存档
```

> **题库**已独立到 `e:\codebuddy\workflow\question-bank\`（见下方「题库」章节），不再放在 `student-profiles/` 下。

> 中文文件名（学生姓名、目录）通过 UTF-8 临时脚本创建/读写，避免 PowerShell/GBK 乱码（见下方「运行环境避坑」）。

## 数据模型

### 学生档案 `students/{姓名}.json`

```json
{
  "name": "学生姓名",
  "grade": "高三",
  "subjects": ["物理"],
  "profile": {
    "整体水平": "中等偏上",
    "薄弱学科": ["物理"],
    "备注": ""
  },
  "errors": []
}
```

### 错题记录（`errors` 数组中的每一项）

```json
{
  "id": "P-20260905-001",
  "subject": "物理",
  "date": "2026-09-05",
  "exam": "顺德一中第四届物理运算",
  "question_no": "第8题",
  "question_text": "题目简述或题干要点",
  "correct_answer": "BD",
  "student_answer": "B",
  "error_type": "概念不清",           // 概念不清/计算失误/审题偏差/方法不会/粗心/时间不足
  "knowledge_point": "电磁感应（线框进入磁场）",
  "exam_point": "安培力、磁通变化、电量、能量守恒",
  "difficulty": "难题",              // 基础/中等/较难/难题
  "question_type": "多选题",          // 选择题/填空题/计算题/解答题/实验题/...
  "review_status": "未复习",          // 未复习/已复习/已掌握
  "review_count": 0,
  "review_history": [],              // [{date, result, note}] 重做记录
  "tags": ["电磁感应", "能量守恒"]
}
```

字段说明：
- `error_type`（错误类型）是诊断关键，务必区分「概念不清」「方法不会」「计算失误」「审题偏差」「粗心」等，这决定了后续是"讲概念"还是"练计算"还是"纠习惯"。
- `id` 规则：`{学科首字母}-{日期}-{序号}`，如物理 `P-20260905-001`、数学 `M-...`、英语 `E-...`、化学 `C-...`、语文 `W-...`。

### 题库 `question-bank/`（分库架构）

统一题库，位于 `e:\codebuddy\workflow\question-bank\`，**按年级/科目分库存放**（如 `question-bank/高三/物理/`），由 `exam-paper-analyzer` skill 批量入库，本 skill 出题时从这里匹配。

- **分库定位（重要）**：按学生的年级 + 学科定位分库 `question-bank/{年级}/{科目}/`——学生是高三物理，就从 `高三/物理/_questions.json` 取题；初三数学则从 `初三/数学/` 取（分库不存在时说明该年级科目还没有题，提示教师先录题）。
- 题目主数据：`question-bank/{年级}/{科目}/_questions.json`（每道题含 `id`、`subject`、`grade`、`source_paper`、`question_no`、`question_text`、`options`、`answer`、`answer_source`、`analysis`、`knowledge_point`、`exam_point`、`difficulty`、`question_type`、`images`）。
- 试卷清单：`question-bank/{年级}/{科目}/_papers.json`。
- 全局概览与 id 计数器：`question-bank/_index.md`、`question-bank/_meta.json`。
- **id 全局唯一**（跨库不重复，如 `Q-00323`），出题引用时无歧义。

## 核心工作流

### 流程一：录入错题（每次考试后）

1. 教师提供试卷 + 学生实际作答情况（哪些题做错了、学生选了什么/写了什么）。
   - 若有现成的试卷分析结果（`exam-paper-output/` 下），直接读取对应学科的逐题分析。
   - 若只有学生标注了错题的试卷图片/文件，先用 `exam-paper-analyzer` 分析试卷，再定位错题。
2. 对每一道错题，提取：题号、题干要点、正确答案、学生答案、所属考点/知识点/题型/难度（从试卷分析结果取）。
3. 判断 `error_type`（错误类型）——这是最需专业判断的一步：
   - 学生答案与正确答案差一个选项、明显漏选 → 可能是「概念不清」或「审题偏差」。
   - 计算过程对但结果错 → 「计算失误」。
   - 完全没思路/空着 → 「方法不会」。
   - 简单题做错、非能力问题 → 「粗心」。
   - 不确定时向教师询问该生出错原因，或标注「待确认」。
4. 把错题追加到对应学生的 `errors` 数组（按 id 规则生成唯一 id），更新 JSON。
5. 重新生成该学生的 Markdown 档案（`students/{姓名}.md`），保持 JSON 与 MD 同步。

### 流程二：诊断薄弱点

1. 读取学生 JSON 的 `errors` 数组。
2. 按 `knowledge_point` 聚合，统计每个知识点出错次数、错误类型分布。
3. 输出「薄弱知识点清单」：按出错次数降序，标注高频薄弱点。
4. 输出「错误类型分布」：概念不清 x 题、计算失误 x 题…… 判断该生是「概念问题」还是「习惯问题」还是「方法问题」。
5. 更新学生档案 `profile`（整体水平、薄弱点、备注）。

### 流程三：定期复习错题

1. 读取学生 `errors`，筛选 `review_status != "已掌握"` 的错题。
2. 按「复习间隔」生成今日复习清单（可结合艾宾浩斯：第 1/3/7/15/30 天）：
   - 距上次复习（或首次记录）满 N 天的题，纳入今日复习。
3. 输出「今日复习清单」，含：题目、考点、学生当时错在哪、上次重做结果。
4. 教师带学生重做后，调用流程四记录结果。

### 流程四：掌握追踪

1. 学生重做某错题后，记录 `review_history` 追加 `{date, result: 对/错, note}`。
2. `review_count` +1。
3. 更新 `review_status`：
   - 连续 2 次做对 → 「已掌握」。
   - 仍做错 → 保持「未复习」，并在 note 里记录新的错因。
4. 更新 JSON 与 MD。

### 流程五：针对性出题（核心价值）

针对某个错题（或某知识点），生成练习题：

1. **明确目标**：该错题的 `knowledge_point`、`exam_point`、`question_type`、`difficulty`。
2. **确定难度**：默认与错题同难度；教师可要求「升一档」或「降一档」。
3. **题库匹配**：先查统一题库 `e:\codebuddy\workflow\question-bank\_questions.json`，匹配 `subject` + `knowledge_point`/`exam_point` + `question_type` + 难度档位相同的题。
   - 命中 → 直接用（附答案与解析，标注来源 `source_paper`）。
   - 未命中 → AI 生成变式题。
4. **AI 生成变式题**（无题库时）：
   - 保持「同考点、同题型」，难度按需持平或升/降一档。
   - 变式要点：换数据、换情境、换设问角度，但考查的知识点与方法不变。
   - 每题必须附：题目、答案、详细解析、难度、考点。
5. **输出练习**：按题生成一份「针对性练习」，含：
   - 学生姓名、对应错题来源、目标考点、难度。
   - 每道练习题的题目、留白作答区、答案与解析（解析可另附，方便教师批改后讲解）。
   - **每道题内部追溯信息**：系统内部可保留出题来源（AI 生成 / 题库 id）、对应日期、对应考试、难度，便于教师追溯；但**学生版试卷正文不显示题库编号/id**，只显示题号、来源/考试简称（可选）与难度等必要信息。
   - **小题标题规范（重要）**：每道小题标题只写「题号 + 来源 + 难度」，**不写「建议用时」**（"建议 X 分钟"这类标注不够专业）；总时长只在卷首/抬头统一说明一次即可。
   - **配图存储规范（重要）**：题目原始配图必须集中保存在题库分库目录 `question-bank/{年级}/{科目}/images/`，并在题目 `images` 字段记录文件名；出卷时 Word 直接从题库图片路径读取并嵌入 `.docx`，Markdown 优先引用题库图片相对路径。除非用户明确要求可移植离线 Markdown 包，否则不要在 `student-profiles/exams/` 下额外生成 `assets_xxx` 图片副本目录，避免把导出版资源误认为题库源数据或残留文件。
6. **同步导出多格式（必做）**：练习生成后，**默认同时输出 Markdown + Word（.docx）两种格式**：
   - Markdown：主文件，便于编辑与版本管理（公式用 LaTeX `$...$` 语法）。
   - Word：用 `python-docx` 生成，每个公式片段拆为多个 run，其中下标 `Run.font.subscript = True`、上标 `Run.font.superscript = True`，渲染真上下标。
   - 两种格式内容一致，文件名相同（仅扩展名不同）。
   - **PDF 输出暂缓（2026-09-05 挂起）**：按用户要求，出试卷时不再默认生成 PDF，该功能挂起（见 `todo/README.md` 低优先级「出试卷 PDF 输出功能」）。技术方案已验证可用（reportlab 富文本 + PIL 分数渲染内联，详见 todo 已完成事项），后续有需要再按该方案重新启用。
7. **公式真上下标 + 真竖式分数（重要，Word 用 OMML）**：
   - **Markdown** 用 LaTeX：`$x_{i}$` 下标、`$x^{2}$` 上标、`$\dfrac{a}{b}$` 分数（渲染器支持时显示为真分数）。
   - **Word 公式必须用 OMML（Office Math）**，已封装在 `scripts/omml_formula.py`：
     - 上标用 `<m:sSup>`（含 `<m:e>` + `<m:sup>`）；下标用 `<m:sSub>`（含 `<m:e>` + `<m:sub>`）；分数用 `<m:f>`（含分子 `<m:e>` + 分母 `<m:e>`）。
     - **关键避坑**：上标不能写成 `<m:rPr>` 里的 `<m:sup/>`；下标不能写成 `<m:sscr>`（这是错误标签，会导致 Word 公式不显示）。必须用 `<m:sSup>`/`<m:sSub>` 结构。
     - 用法：`add_formula(p, "\\frac{B^2^L^2^v~0~}{mR}")`，标记 `~x~` 下标、`^x^` 上标、`\frac{num}{den}` 分数。
     - **LaTeX 转 OMML 标记避坑（2026-09-06 新增）**：从题库/Markdown 的 `$...$` 公式转入 `add_formula` 前，必须先正确处理 LaTeX 命令，且**禁止在解析分数前全局删除花括号**。错误示例：先 `re.sub(r'\{([^{}]*)\}', r'\1', s)` 会把 `\frac{1}{3}` 破坏成 `\frac13`，导致 `omml_formula.py` 无法识别真分数，Word 中出现公式乱码/命令文本。正确顺序：① 把 `\dfrac` 规范成 `\frac`（匹配单反斜杠 LaTeX 命令）；② 保留 `\frac{num}{den}` 的 `{}` 交给 `omml_formula.py` 解析；③ 只对非分数结构做上下标标记转换（如 `x^{2}` → `x^2^`、`x_{0}` → `x~0~`），并且**先处理无花括号上下标，再处理有花括号上下标，禁止二次转换**（否则 `a^{5}` 会变成 `a^5^^`，Word 中残留可见 `^`）；④ `\sqrt{...}` 必须由 `omml_formula.py` 生成 Word 原生 `<m:rad>` 根号，禁止转成普通字符 `√(...)`；⑤ 常见普通 LaTeX 转义必须在 Word 输出前清理成人类可读符号：`\%`→`%`、`\ `→空格、`\div`→`÷`、`\times`→`×`、`\to`→`→`、`\Delta`→`Δ`、`\neq`→`≠`、`\ge`→`≥`、`\le`→`≤`、`\[4pt]`→`; `；⑥ 不支持的 LaTeX 命令要先显式转换为普通数学符号或拆成多个 OMML 节点，不能原样塞进 `<m:t>`。
   - **PDF**（**功能挂起中**，以下规范仅作重新启用时的技术沉淀，当前默认不输出 PDF）公式必须用真上下标 + 真分数：
     - 真上下标：reportlab `Paragraph` 用 `<sub>`/`<sup>` 标签。
     - 真分数：用 PIL 渲染分数为 PNG（分子/分数线/分母），Paragraph 用 `<img src="..." valign="middle"/>` **内联**到文字行内。关键：`valign="middle"` 让分数与文字基线对齐；**不要用 `valign="-7"`**（会让分数悬空偏下）或 `Flowable` 块级元素（分数会单独占行）。
       - 分子分母如果含 `<i>`/`<sub>`/`<sup>`，渲染前用 `strip_tags` 去掉标签（保留纯文本），外层富文本标签维持上下标和斜体（在分数图周围）。
       - 缓存：相同 (分子, 分母) 用 hash 作为文件名复用 PNG，避免重复渲染。
   - **禁止**：Word/PDF 中用 Unicode 上下标字符（`₁₂₃⁰¹²³`）或斜杠 `/` 写法表示分数（字形不一致、与正文数字易混淆）。
   - **递归处理**：混合片段列表可能含嵌套 list（一个分析点含文字+分数），处理函数必须递归遍历，否则嵌套层里的分数会被丢弃。
8. **字体规范（Word 版，全科目统一，重要）**：
   - **中文**：一律用 **宋体**（`SimSun`），通过 run 的 `rFonts` 的 `w:eastAsia` 设置。
   - **英文 / 数字正文**：统一用 **Times New Roman**（`ascii`/`hAnsi`），与宋体是标准学术排版搭配，美观且稳妥。
   - **数学公式（OMML）**：使用 **Word 原生公式字体 Cambria Math**（不手动改公式字体）——它是 Office 数学排版专用字体，含完整数学符号集，专业且不易出错；**不要**把公式字体强行改成宋体或 Times New Roman（会缺符号或变难看）。
   - **禁止**：正文里混用多种西文字体（如 Arial 与 Times 混排）；中文不用默认的等线/黑体冒充正文。
   - 落地做法：`doc.styles['Normal']` 设置 `font.name='Times New Roman'` 且 `eastAsia='宋体'`，正文 run 不另行覆盖；公式走 OMML 原生即可。
9. **可选**：把 AI 生成的优质题目回填到统一题库 `question-bank/_questions.json`，积累题库（id 规则 `Q-` + 5 位全局递增序号，如 `Q-00323`）。

## 输出文件保存规范

- 学生数据统一存 `e:\codebuddy\workflow\student-profiles\` 下。
- 学生 JSON 主数据：`students/{姓名}.json`。
- 学生可读档案：`students/{姓名}.md`（从 JSON 生成）。
- 针对性练习：`student-profiles/exams/针对性练习_{YYYYMMDD}_{学生}_{学科}_{考点}`（同一份内容输出 `.md`、`.docx`、`.pdf` 三种格式）。
- **练习命名必须带归属（重要）**：从题库抽题生成的练习，文件名必须注明**归属学生**或**测试标识**，方便后续查找：
  - 有归属学生：`练习_{YYYYMMDD}_{学生姓名}_{学科}_{时长或用途}.md`，如 `练习_20260905_连可欣_物理_30分钟.md`
  - 无归属/测试用：`练习_{YYYYMMDD}_测试_{学科}_{时长或用途}.md`，如 `练习_20260905_测试_物理_30分钟.md`
  - 练习正文标题同步标注：`{学生姓名}的练习` 或 `测试练习`。
- 创建中文文件名/目录时用 UTF-8 临时脚本，避免乱码。

## 运行环境避坑（Windows 中文编码）

与 `exam-paper-analyzer`、`classroom-audio-evaluation` 相同的坑：在 Windows 上命令行直接写中文参数/路径会因 GBK/UTF-8 不一致而乱码。规则：

1. 不要直接在命令行写中文参数/路径。改用 UTF-8 临时脚本（ASCII 文件名）硬编码中文路径/内容，再 `python _task.py` 执行。
2. JSON/Markdown 文件内容本身用 UTF-8 读写，不受影响。
3. 读写 JSON 时显式 `encoding="utf-8"`，`json.dump(..., ensure_ascii=False, indent=2)`。

## 临时文件规范（工作区统一约定）

- 运行中的一切临时文件（UTF-8 中文脚本、AI 生成变式题的中间脚本、解析缓存等）**统一放入工作区 `_tmp/` 目录**（已被 `.gitignore` 排除），禁止散落在根目录或正式数据目录（`student-profiles/`、`question-bank/` 等）。
- 结束时执行**一条命令**一键清理，禁止逐个文件删除（会多次打扰用户确认）：

  ```
  python .codebuddy/scripts/cleanup_tmp.py
  ```

  支持 `--dry-run`（预览不删）与 `--legacy`（额外清理根目录遗留 `*_work/` 目录）。脚本只删 `_tmp/`，不触碰任何正式目录。
